# v1.5.4

## ✨ 调节灯更快了 · 不再"闲置后第一下卡 5 秒"

v1.5.4 集中解决调节速度的两个体验问题：**闲置一阵后再调亮度明显变慢 / 卡顿**，以及**从关灯状态直接拖滑杆首调慢半拍**。

## 🐛 修复

### 闲置后首包被吞、调节卡 ~5s → 改为局域网级超时 + 快速重试

排查（带毫秒级的网络/锁打点实测）发现根因：**闲置几分钟后第一次操作，首条命令在链路重建窗口被吞/无响应，python-miio 会默认干等 `5s` 超时才重试**，这 5 秒里你对同一盏灯的连续调节全被锁内排队顶住，等锁一放、命令一次性爆出——表现为"生效延迟于好几次操作"。

- 局域网实测正常往返仅 ~150ms（峰值 ~300ms），5s 的默认超时对局域网严重过剩。
- 新版把发送超时降到 **0.3s**（不低于实测峰值，避免误判正常命令），首包被吞时协议的**内置重试立即接管**，闲置后第一次操作的恢复耗时从 **~5s 压到 ~0.5s**。

### 从关到调改为并发点亮，首调不再慢一拍

- 关灯状态拖滑杆时，此前要先 `on()` 等返回、再发亮度命令，**两次串行往返**拖慢首调。
- 新版点亮动作交给**独立并发路径**，与亮度命令并行，首调近似只花一次命令的往返。

## 🧹 其它

- **手动调整不再被晚到的旧读取覆盖**：你在飞控里调好亮度后，一次滞后于调整的旧状态读取不会拿旧值回退它；之后的刷新仍会从设备读回真实状态（外部改动照样能带回）。
- 多灯保持并行刷新，一台慢不阻塞其它设备。
